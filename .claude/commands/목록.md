# /목록 — 오늘 글감 목록

운영자가 **"목록"**, `/목록`, "글감 보여줘", "오늘 뭐 쓸까"라고 하면 실행한다.

원본은 awoo `.claude/commands/목록.md`. calculatorhost 는 **자동화가 없다**(GitHub Actions 10개 전부 꺼짐, 2026-09-30 운영자 지시 "혼자 하는 액션은 모두 멈춰"). 그래서 봇이 큐를 미리 만들어 두지 않는다. **운영자가 목록을 열 때만** 이 세션에서 API 를 불러 다시 만든다. 배경은 `docs/ops/SITE-KEYWORD-PROFILE.md`.

## 순서

1. **최신화.** 큐가 오늘 것이 아니면(`docs/ops/pipeline-queue.json` 의 `meta.today` ≠ 오늘 KST, 또는 파일 없음) 다시 만든다.
   ```bash
   node scripts/keyword-pipeline.mjs --serp
   ```
   - 검색량(데이터랩)은 기존 개발자센터 키로도 잰다. 검색 결과 정찰(webkr)은 **NAVER API HUB 키**(`.env.local` 의 `NCP_API_KEY_ID`·`NCP_API_KEY`)가 있어야 한다. 키가 없으면 1회 401 후 바로 멈추고, 전부 "실측 대기"로 남는다. 키 값은 읽지도 출력하지도 않는다.
   - 정찰 예산은 기본 35건(검색량 큰 순). 7일 안에 잰 결과는 다시 쓰고 API 를 부르지 않는다.
   - 큐가 오늘 것이면 이 단계를 건너뛴다.
2. **띄우기.** 출력 HTML 조각을 그대로 `mcp__visualize__show_widget`(title `calculatorhost_today_post_picks`)으로 채팅에 띄운다. 먼저 `mcp__visualize__read_me` modules `["interactive"]` 를 호출한다.
   ```bash
   node scripts/ops-widget.mjs --limit=8
   ```
3. **수량 한 줄.** `node scripts/ops-widget.mjs --count` 출력을 그대로 쓴다(`오늘 발행 N건 · 어제 N건 (수동 전용)`).
4. **쉬운 말 요약 두세 줄.**
   - 자리가 열린 글감이 몇 건이고 1순위가 무엇인지.
   - "다음에 크게 뜰 주제" 칸에서 지금 준비할 것(선점 적기·곧 뜸)과 새 글을 멈출 것(꺾이는 중).
   - 달러 숫자는 **가정 RPM $5** 추정이라는 것. 애드센스 실자료가 생기면 `docs/ops/adsense-private/rpm-groups.json` 을 고친다.
5. **끝.** 다른 카드(순위·트래픽)는 보여주지 않는다.

## 목록 읽는 법

| 칸 | 뜻 |
|---|---|
| 오늘 쓸 글감 | 실측했고 노출 가능성 45 이상. 노출 가능성 × 수익 배수 큰 순. 배수는 지금 전부 1.0(운영자 결정 2026-10-07) |
| 실측 대기 | 검색량은 있지만 검색 결과를 아직 안 잼. 점수를 지어내지 않는다 |
| 하루 약 N달러 | 1~3위에 들었을 때 추정. 데이터랩 최근 7일(실업급여=100) × 50명 × 1.2 PV × RPM $5 ÷ 1000 ÷ 7. 50은 awoo 실측 계수라 계산기 검색어에선 다를 수 있다 |
| 네이버 자체 계산기 위젯이 있을 수 있음 | `big-keywords.json` 의 `widgetRisk`. 웹문서가 한참 아래로 밀릴 수 있어 눈 확인이 특히 중요 |
| 다음에 크게 뜰 주제 | `docs/ops/landgrab-calendar.json`(작년 피크 기준 준비 마감일) + 이번에 잰 검색량 추세(직전 3주 대비 1.2배 이상 = 뜨는 중, 0.6배 이하 = 꺾이는 중) |

노출 가능성 점수 규칙은 `scripts/lib/exposure.mjs`, 처리 방식은 큐 항목 `action.type`:

| action | 뜻 |
|---|---|
| `calculator` | 새 글 대신 그 계산기 페이지 본문·예시 보강 |
| `guide` | 제목에 검색어가 통째로 든 기존 가이드가 있다. 새 글 대신 그 글 보강 |
| `new` | 새 가이드 |
| `new-calculator` | 계산기 자체가 없다. 운영자 결정 필요(공식·TDD 작업) |

## 버튼 동작

버튼은 `sendPrompt` 로 아래 문장을 채팅에 넣는다. 문장은 슬래시로 시작하지 않는다(앱이 명령으로 해석해 전송을 놓친다, awoo 2026-09-25).

- **발행 지시 ↗** → `발행: <쿼리> — 대시보드 지시(큐 <id>)…`. `/post` 의 "대시보드 버튼 지시" 절차를 따른다.
- **보류** → `보류: "<쿼리>" …`. 큐 항목 `status` 를 `hold`, `statusAt` 을 오늘로 바꾸고 끝낸다. 이유는 묻지 않는다. 큐는 로컬 전용(gitignore)이라 커밋하지 않는다.
- **실측 ↗** → `실측: "<쿼리>" …`. 그 쿼리만 정찰하고 목록을 다시 띄운다.
  ```bash
  node scripts/keyword-pipeline.mjs --scout="<쿼리>"
  ```
- **[첫 화면] [한 번 스크롤] [그 아래]** → `눈확인: "<쿼리>" = <값> …`. 운영자가 네이버에서 직접 보고 웹문서 묶음 위치를 누른 것이다. 공식 API 로는 잴 수 없다. **Claude 는 네이버 화면을 대신 보지 않는다**(검색 결과 HTML 수집은 robots.txt 금지).
  ```bash
  node scripts/eye-offset.mjs --query="<쿼리>" --value="<첫 화면|한 번 스크롤|그 아래>"
  node scripts/keyword-pipeline.mjs --serp-replay
  ```
  `그 아래` 면 그 후보는 닫힘으로 빠진다. 기록은 `docs/ops/eye-offset.json`(로컬, 7일 지나면 무시). 그다음 2~4단계를 다시 한다.
- **선점 ↗** (다음에 크게 뜰 주제 칸) → `선점: "<주제>" …`. 캘린더 항목을 준비 마감일 전이라도 오늘 후보로 당긴다.
  ```bash
  node scripts/keyword-pipeline.mjs --scout="<주제>"
  ```
  캘린더에 있는 주제면 그 처리 방식(계산기 보강·신규 계산기)을 그대로 가져와 `빈틈:<주제>` 항목으로 넣는다(21일 유지, 매번 다시 잰다). **선점은 목록에 올리는 것까지다. 글은 운영자가 그 항목의 [발행 지시]를 눌러야 쓴다.**

## 금지

- 발행은 운영자가 버튼을 누르거나 직접 지시할 때만. 목록을 보여주면서 먼저 쓰지 않는다.
- 예약 실행·루틴·GitHub Actions 로 이 목록을 자동 갱신하지 않는다(운영자 지시 2026-09-30).
- 네이버 검색 결과 페이지를 브라우저·스크립트로 긁지 않는다. 공식 API 만 쓴다.
