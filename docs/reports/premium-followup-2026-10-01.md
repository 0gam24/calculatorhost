# 홈·급여·대출 UI 후속 개선 — 로컬 검증

운영 기준은 `0d871e2b083df718eae62a061ede7a5e2ccf8852`, 작업 브랜치는 `codex/premium-followup-2026`이다. 이 후속 작업은 로컬 개발·검증이며 원격 push와 추가 배포는 하지 않았다. 미배포 API `93487b0`과 홈 데이터 `5641010`은 별도 브랜치에 그대로 보존했다.

## 변경과 목적

- 공통 결과 헤더를 절제된 민트/다크 틸 영역으로 구분했다. 핵심 숫자는 모바일 32px, 390px 이상 40px, 데스크톱 48px이며 큰 금액도 줄바꿈한다. 주요 결과 하나·보조 최대 세 개·상세 접기를 유지한다. 이 스타일과 독립된 다음 계산 영역은 31개 계산기의 공통 ResultCard에 적용된다.
- 결과 카드와 다음 계산 영역을 형제 영역으로 분리했다. 입력 오류나 지원 조건 미확인 상태에서는 결과 복사와 다음 계산을 표시하지 않는다. 급여에서 사용자가 직접 정한 저축액만 적금으로 전달하는 기존 흐름을 유지한다.
- 급여의 연봉/월급/목표 실수령액과 대출 원금에 실제 금액으로 교체하는 프리셋 세 개를 보이게 했다. 기존 더하기 버튼은 그대로 별도 기능이다. 같은 프리셋 재선택도 빈값·잘못된 초안을 복구하며, 선택한 원/만원 단위와 정확한 원 단위 값을 보존한다. 대기 중 입력이 나중에 프리셋을 덮어쓰지 않도록 타이머를 취소한다.
- 대출의 핵심 결과를 원리금균등 일반 조건에서는 ‘매달 갚을 금액’, 원금균등·만기일시·거치 조건에서는 ‘첫 달 갚을 금액’으로 표시한다. 기존 첫 달 값을 사용하고 마지막 달 값은 상세 수치로 유지한다. 상환 방식·만기 원금·거치 중 이자 설명을 함께 표시한다.
- 홈의 자주 찾는 계산기는 빠른 진입 카드, 목적별 흐름은 간결한 세로선 영역, 전체 계산기는 구분된 목록으로 역할을 나눴다. 최소 헤더와 검색은 보존했다. 홈 이용안내·Footer와 실제 허브/안내 페이지의 Sidebar에서 `/guide/` 표시만 ‘계산·생활정보’로 바꿨다.

변경 소스는 UI 9개 파일(새 AmountPresets 포함), 의미 있는 프리셋 상태 회귀 테스트 1개 파일, 이 보고서다. 산식·상수·금융 데이터·API·배포 스크립트·의존성·workflow는 변경하지 않았다. 급여/대출 page metadata와 기존 URL·SSR 설명·구조화 데이터를 보존했다. 홈 FAQ와 ItemList도 유지했다.

## 실제 실행 검증

- 전체 단위 테스트 68파일/1,284개 통과. 신규 세 검사는 동일 프리셋 오류 복구, 만원 단위 보존, 지연 입력과 프리셋의 충돌 방지를 다룬다.
- typecheck와 lint 통과. 실제 `npm run build`의 prebuild/build/postbuild 통과, 503 정적 페이지. 빌드 외부 요청·비공개 파일 읽기 시도 0이다.
- Chrome 격리 프로필의 로컬 산출물 검사 77/77 통과. 360/390/1440px 라이트·다크, CSS 200% 확대, 키보드 입력/라디오/버튼, 결과 focus·aria-live·오류 연결, 단위 전환, 반복/긴/빈/0/잘못된 입력, 급여→선택한 저축액→적금→뒤로가기, 독립 대출 사례, 전체 31개 smoke와 런타임/개인정보 이벤트 검사를 포함한다.
- 첫 브라우저 실행의 두 실패는 프리셋 클릭 직후 React 갱신을 기다리지 않은 검사 기대값 경합이었다. 프리셋의 명시된 금액으로 독립 기대값을 구하고 갱신을 기다리도록 스크립트를 수정했다. 사이트 소스 수정 없이 최종 77개가 통과했다.
- 새 결과/다음 영역의 계산된 텍스트 색상 대비 라이트·다크 표본 10개: 최소 7.61:1. 전체 접근성 인증을 의미하지 않는다.
- 공개 HTML 444개에서 관련 작성도구 문구 0회. 기술 식별자·내부 개발 문서는 유지했다.
- 새 out의 sitemap 435개 각각 파일 존재·self canonical·H1 하나·index 허용·JSON-LD 파싱 통과. 기존 대비 435페이지의 제목/설명/OG/robots/canonical/JSON-LD/H1 묶음과 lastmod 모두 동일하다. 홈 SSR 링크 31개와 `/guide/` 경로를 유지했다. 참조 정적 asset 454개가 모두 존재하며 Googlebot/Yeti에 적용되는 robots 규칙은 `/_next/static/`, `/_next/image`를 허용한다.
- 새 라이브러리는 추가하지 않았다. 빌드가 표시한 First Load JS는 대출 132→133kB, 급여 135→136kB, 공통 102kB 유지다. 반올림된 빌드 표 수치이며 실제 field CWV 측정은 아니다.

## 기술 SEO 기준과 측정 한계

좁은 UI 변경 범위에서는 신규 기술 SEO 차단을 발견하지 못했다. [Google crawlable links](https://developers.google.com/search/docs/crawling-indexing/links-crawlable), [JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [sitemap 생성](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [Naver 리소스·링크](https://searchadvisor.naver.com/guide/resource-and-link), [Naver JavaScript](https://searchadvisor.naver.com/guide/seo-advanced-javascript)를 대조했다. 실제 재색인·검색 스니펫·순위 변화는 측정하지 않았다.

200% 검사는 CSS root zoom이며 실제 Chrome 브라우저 줌과 미디어쿼리 동작이 다를 수 있다. 스크린리더 호환 구조는 role/name/focus/ARIA로 확인했지만 실제 스크린리더를 실행하지 않았다. 브라우저 QA는 모든 first-party 응답을 로컬 out에서 제공하고 외부 광고·분석·데이터 요청을 차단했다. 실제 광고 노출, GA4 수신, field CWV, 유입과 수익 효과는 미검증이다. 기존 API 404와 법령 레지스트리 잔여는 이 UI 변경에서 해결했다고 주장하지 않는다.

독자가 결과를 읽고 관련 계산을 이어가기 쉽게 만드는 것이 목적이다. 월 수익·검색 순위를 보장하지 않으며, 별도 운영 반영 후 기존 계산 완료/다음 계산 이벤트와 비교 가능한 유입·수익 기간으로 효과를 확인해야 한다. 금융 입력값은 URL·분석 이벤트에 새로 전송하지 않는다.

## 스크린샷과 보존

로컬 새 UI의 실제 캡처 30장과 결과 초점 캡처 2장을 저장소 밖 `preview-evidence/premium-followup-*`, `premium-review-*`에 보존했다. 홈 모바일·급여 데스크톱·대출 모바일 결과 대표 세 장을 Library에 저장했다. 이 이미지는 현재 운영 사이트 화면으로 표시해서는 안 된다.

보고서와 코드만 로컬 브랜치에 보존한다. 사용자 원본 개발 폴더 main은 운영 `0d871e2`를 유지하며 기존 사용자 파일, 자동화 10개 OFF, 광고 계정 설정을 보존한다. 추가 운영 배포는 이 결과 검토 뒤 별도 지시에 따른다.
